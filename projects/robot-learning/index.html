01 / Problem

A custom embodiment breaks the assumptions of an off-the-shelf learning stack.

The robot combines a non-standard five-joint arm, a dexterous hand, constrained orientation freedom, and hardware that does not yet expose a complete LeRobot-compatible control path.

The first engineering problem is therefore not policy training. It is creating a trustworthy path from human motion to bounded robot commands while keeping the robot model, joint limits, workspace, visualization, and future dataset schema consistent.

The project deliberately validates each boundary without motors first. Physical control remains blocked until motor model, CAN interface, joint signs, and zero offsets are verified.

01

Embodiment configuration

Joint limits, workspace, home pose, scale, and tool frames are derived from the registered URDF into one generated configuration instead of being duplicated across the stack.

02

Operator mapping

Grip acts as a clutch, trigger controls grasp, controller pose supplies the end-effector target, and explicit reset and yaw controls avoid unsafe mirrored mappings.

03

Safety boundary

Soft start, velocity limiting, joint-limit margins, command divergence checks, a 0.5-second watchdog, and trip-state freezing sit ahead of the unfinished motor backend.

04 / Status

What works now, and what does not.

Validated

  • Quest controller and hand-tracking input
  • Coordinate transforms and clutch behavior
  • URDF-driven configuration and IK
  • Dashboard and virtual robot visualization
  • Safety-layer behavior with a mock motor backend

Still open

  • Verified motor model, CAN interface, signs, and zero offsets
  • Physical arm actuation through the production backend
  • LeRobot episode collection on the final embodiment
  • ACT or VLA training and physical policy evaluation
