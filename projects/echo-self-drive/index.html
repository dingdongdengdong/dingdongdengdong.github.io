01 / System boundary

The robot’s visual shell follows physical state; it does not control the physics.

A dedicated differential-drive proxy controls collision and motion; the preserved Echo Full CAD shell follows the proxy’s measured PhysX pose after each simulation step.

The runtime preserves the original Echo, VICA, and SuperArm source trees. Derived URDF and USD assets carry the physics and composition needed for the road scenario without modifying original source files.

Commands enter through ROS 2 /cmd_vel, pass through a safety-gated command multiplexer, and drive the proxy. Odometry, joint state, TF, RGB, IMU, and RTX LiDAR remain explicit sensor interfaces.

04 / Full-road acceptance

A successful run must complete the route without bypassing sensor input.

Gate 01

Pedestrian wait

The mission stops for the pedestrian condition and resumes only after the route clears.

Gate 02

LiDAR detour

Obstacle handling consumes fresh RTX LiDAR ROS measurements rather than predefined scene coordinates.

Gate 03

Terrain course

The run traverses both speed bumps, a right turn, crowned roadway, and an unpaved segment.

Gate 04

Terminal stop

The robot reaches the endpoint with stable wheel contact and a confirmed zero-velocity command.

05 / Integrated embodiment

The mobile base can carry SuperArm + AmazingHand without giving manipulation control to Nav2.

Mount

Derived physical attachment

A derived SuperArm + AmazingHand asset mounts at the front crossbar while the mobile-base proxy remains the only locomotion authority.

Interlock

Drive-stow before motion

The road launcher folds the arm into its drive-stow pose before releasing the wheel-command interlock.

Sensor split

Wrist D435i stays scoped

Wrist RGB, aligned depth, and IMU support manipulation proofs; road navigation instead uses chassis RGB and RTX LiDAR.

06 / Evidence boundary

The proof is strong because its untested categories stay explicit.

Verified by recorded evidence

  • Full road-course completion from the original start
  • Pedestrian stop and clear behavior
  • Sensor-confirmed RTX LiDAR detour
  • Both speed bumps and mixed road surfaces
  • Stable contact and confirmed terminal stop

Separate or unclaimed

  • Injected-fault acceptance in the recorded full-road run
  • Viewport LiDAR debug-draw evidence
  • Manipulation grasp or contact validation while driving
  • Deployment on a physical road
  • Docker images, drivers, and NGC credentials inside the package
